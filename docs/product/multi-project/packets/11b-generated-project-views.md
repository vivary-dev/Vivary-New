## Goal

Give the user a useful project map and current-state view with visible sources,
without creating two writable owners or discarding existing notes.

## Context

Read [ENGINEERING.md](../../../../ENGINEERING.md), the [current design](../design.md),
[Agent-Native ownership](../native-owners.md), and the [original source map](../research/original-vivary-product-map.md).
Agent-Native owns application actions, runs, and conversations. The original
creator owns setup operations, and Tropo owns project retrieval. The coordinating
agent (`root`) assigns one source writer before activation. Follow the live
repository delivery rules.

The original creator assigns STATE.md to one human/orchestrator, gives it
free-form fields, and preserves it during adoption. Changing it to generated
output is a migration, not an unchanged five-file contract. Research D1-D5 do
not supply that migration decision. Begin with read-only derived views if appropriate.

## Owned files

- Existing project graph/retrieval adapters and Workbench map/state presentation.
- A deterministic view renderer beside its existing data owner, if persisted output is needed.
- Original creator/adopter migration helpers only after the state contract is resolved.
- Focused view/migration tests and the normal GUI map/state journey.

## Done condition

The map links supported existing project material and clearly distinguishes
observed data, authored guidance, unavailable sources, and generated output.
The state view names its authoritative task/record inputs. A graph with no edges
is not automatically unhealthy, and a generated index does not create authority.

Authored STATE.md remains intact unless an explicit reviewed migration preserves
its unmatched content and defines the new writer. Generated bytes are reproducible
and clearly read-only. Corrections go to the owning input, not a competing copy.
The GUI opens the source of a displayed fact and remains usable with missing inputs.

## Verify

Check generation from real selected inputs, authored free-form state, an absent
source, changed input, and a valid edgeless workspace. If migration is selected,
prove preservation, conflict refusal, retry, and restoration of the previous state.
Exercise the resulting map and state view through the real application.

```console
pnpm --dir packages/workbench typecheck
python -m unittest discover -s packages/create-vivary/tests -p test_adopt.py
git diff --check
```

## Stop conditions

Do not silently replace STATE.md, infer facts from absent task history, introduce
an event store, or force every workspace to carry a generated index. Unresolved
migration semantics block that migration only, not useful read-only views.
